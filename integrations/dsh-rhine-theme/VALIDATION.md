# 验证记录

## 原生窗口安装完整性与修复（1.0.1，2026-10-07）

本地 Windows Desktop 0.2.0-rc.2 实例出现主题正常显示、全屏和 70% 最小面积限制同时失效。preload 桥接与窗口策略文件仍在，但主进程入口缺少策略导入；渲染器请求报告 `No handler registered for 'rhine-desktop:scene-policy'`。已确认不完整安装状态，未确认是哪次操作移除了导入。

- 原生 `check` 现在检查主进程导入、preload 桥接、窗口策略内容及标题栏适配，区分宿主兼容与完整安装。`install` 保留逐次备份及其他补丁，并在写入后验证完整性。
- 本贡献目录 `npm test` 45 项通过；使用匹配宿主声明的严格类型检查通过。
- `npm run release` 生成 1.0.1；两个模型继续逐字节无损还原。新版 ZIP 中每个文件均通过 `CONTENTS.sha256` 校验。
- 发布验证在 ASAR 和解包两种模拟安装中移除主进程导入、保留 preload/策略文件，确认只读检查指出缺失入口；重新安装后完整性恢复，第三方补丁保留，卸载和不兼容版本拒绝继续通过。
- 设置 `DSH_SOURCE_ROOT` 后，使用真实 Desktop 插件管理器后端在临时 profile 安装、激活及卸载 1.0.1 TGZ 通过；host 入口可导入，运行包没有构建脚本或开发依赖。
- 同一原生策略在本地实机完成 13 项检查：全屏启动、主题按钮、设置按钮、F11、长按防重复、退出全屏居中、缩小限制、减少动态和强制颜色、停用恢复及页面重载均通过，无原生桥接错误。2560 × 1392 DIP 工作区对应最小尺寸 2142 × 1165 DIP，面积约 70.03%；请求缩至 640 × 480 时仍保持下限。

窗口策略与主题视觉未改动。1.0.1 完善诊断与重装修复，不会阻止后续 DSH 更新覆盖应用文件；遇到相同情况需使用原生工具重新检查和修复。本机日志、会话标题、用户配置与备份未纳入提交或发布包。

## 关闭主题白屏修复（2026-10-05）

DSH Desktop 0.2.0-rc.2 中，关闭主题时撤销插槽声明可能先于旧 RHINE 组件停止渲染，触发 `sidebar.settings` 未声明错误并使根界面空白。启动时先使用默认启用值、再读取已保存的关闭值，也会触发相同问题。

- 配置就绪前不接管宿主插槽，已保存为关闭时直接使用原生界面。
- 关闭正在运行的主题后自动刷新界面，从持久化的关闭状态重新加载；不在旧组件仍挂载时撤销其插槽契约。这是当前宿主版本的兼容处理。
- 新增两个执行真实客户端 `apply` 生命周期的回归测试，覆盖异步读取关闭配置和关闭主题时先刷新、未撤销插槽的行为。
- 对同一源码的本地 Desktop 构建实测“启用 → 关闭 → 重新加载”：原生账号菜单恢复、RHINE 根组件移除、无插槽错误及控制台错误。


## 既有主题验证（2026-10-04 至 2026-10-05）

环境为 Windows、DSH Desktop 0.2.0-rc.2、Ryzen 5 7600X 与 RX 7900 XT，目标显示分辨率 1440p。以下是此前本地主题验证摘要，不是此次 PR 的 CI 结果。

- 41 项自动测试通过，覆盖适配器、偏好、开场、窗口策略、原生补丁和无损资源处理。
- 12 项实机专注检查通过，包含中途反向、体素跟随、编辑器和草稿保持、减少动态效果及回到休眠。专注展开/收起各发生一次聊天面板布局，动画中间帧通过 transform 缩放已布局内容。
- 高频悬停压力输入：12 个帧批次，每批 16 次移动，另有一次移出前移动。射线拾取 193 → 12 次；含一次即时点击的累计拾取 CPU 为 411.4 → 34.1 ms，12 个最终悬停目标相同。这不代表整体 CPU 下降相同比例。
- AO 两个中间目标省去不使用的深度附件：1440p 高精度设置少分配 1,843,200 个深度像素，按每像素 4 字节约 7.03 MiB 理论存储。未测量真实进程 VRAM 差值。
- 上述 AO 附件改动在首页、项目过渡、聊天过渡、聊天静止、浅色和 900×900 视口六组固定输入比较中，RGBA 字节无差异。未使用降低精度的单通道 AO 实验。
- 稳定聊天画面在一次 3 秒追踪中无 RAF、布局或样式重算事件。首页 GPU 的常规前后采样约为 5.90 → 5.90 ms，未证明普遍 GPU 提速。
- 发布包已在隔离 profile 通过真实 DSH 插件管理器后端安装/激活/卸载验证；原生工具通过 ASAR 与解包两种模拟安装布局的安装/更新/卸载测试，保留第三方 preload 修改，并拒绝不兼容版本。

原始本地 profile、历史备份、性能 trace 和会话截图不随本贡献上传。源码附带可独立运行的自动测试、发布验证和可选实机专注验证；执行方法见 README。CI 明确区分无需宿主的测试与需匹配 DSH 源码/运行实例的测试。

## PR 整理原则

导入生产源码与资源，保持已验证的运行逻辑；将构建检查使用的本机路径改为显式环境变量，实机脚本改为使用当前测试会话。重新在本贡献目录安装依赖、执行自动测试、类型检查和打包，并对新旧构建客户端/宿主入口进行哈希比较，结果以 PR 说明为准。

macOS、Linux 和其他 DSH 版本均未验证。
